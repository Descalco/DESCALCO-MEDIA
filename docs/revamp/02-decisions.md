# 02 — Locked Decisions

Decisions settled as of **2026-08-08**. Each records the reasoning and what was rejected, so they don't get relitigated.

---

## D1 — Framework: Next.js (App Router)

**Decided.** Overrides the original audit's Astro recommendation.

The handoff document justified this on the grounds that an SPA is required for persistent background state and seamless thumbnail→hero transitions. **That justification is overstated** — Astro's View Transitions with `transition:persist` handles persistent canvases and audio across navigations, and GSAP Flip works identically in both.

**The reason that actually holds is React fluency.** Fighting an unfamiliar templating language while simultaneously inventing a motion system is a real risk, and the upcoming software case studies (Money Trail, Arkive, Cull) make owning a React stack sensible long-term.

**Accepted trade-off:** Next.js costs more discipline on payload. Media must be strictly lazy-loaded and GSAP instances must be cleaned up on unmount or they leak.

**Counterweight — see [05](05-references.md):** two of the three reference sites chosen as aspirational are on Squarespace and Cargo.site, and the closest structural match (Ordinary Folk) is on Webflow. The framework is not the differentiator. Build the boring version well.

## D2 — Backoffice stays isolated

**Decided.** The existing Node/express backoffice (session auth, rate limiting, uploads) remains as-is. It is not migrated into Next.js.

**Critical correction to the handoff document:** it specifies that Next.js will "fetch the structured JSON data generated by the Node backend at build time." This **cannot work** — the backoffice is a local server with no public address, so a Netlify or Vercel build has nothing to fetch from.

**The version that works:**

1. Run the backoffice locally
2. Run `generate-portfolio-data.js`
3. Commit the generated output
4. Next.js reads it **from disk** at build time

Same outcome, no hosting requirement, no public attack surface.

**Always consume the generated artifact, never `backoffice/data/projects.json` directly** — see [01](01-audit-review.md#3-two-records-in-projectsjson-are-malformed).

## D3 — Language: English only

**Decided.** Reversed from an initial bilingual PT/EN choice.

Removes the entire i18n workstream: no `[locale]` routing, no doubled content schema, no hreflang, no language switcher.

*For the record, had bilingual gone ahead the scope was ~4,500 translatable words site-wide, with `sof-week.html` alone accounting for 1,495.*

## D8 — Relationship as the organising axis — as ordering, not tabs

**Decided 2026-08-08, revised same day.**

**Replaces** the discipline filters proposed by both the audit and the handoff (Motion Design / 3D / Branding / UX-Web / Interactive / Play). Those would have shipped with half returning one or zero results — including **zero for UX/Web**.

**The axis is relationship** — who the work was for — not discipline. Nobody asks what discipline a personal project belongs to, and relationship groupings always have content.

**But it expresses as curated ordering and card metadata, not filter tabs.** Filters are a function of scale: Richprjcts filters because it has 50+ projects; Vucko (20) and Ordinary Folk (~10) show a plain curated index. At **13**, tabs are over-structure — and a `Clients` tab would spotlight Limifield ×4, the weakest work, inviting the comparison a junior loses.

**Schema keeps `relation`** (`client` | `personal` | `collaboration` | `reel`) so tabs can be switched on later with no migration. Revisit at 25–30 projects.

**Consequences:**
- The `client-group` entry type is **not needed** — schema simplifies
- Discipline survives as **card metadata** and as **capability pages** (the Burocratik `/branding` pattern), not as a filter axis
- **Credits and awards become a first-class card system** — "with Ocubo · Best Public Project" does more for a junior than any filter
- **Reel is a top-level nav item**, `/reel/2026` from day one, `/reel` always resolving to newest

Full reasoning in [03](03-curation.md#taxonomy--revised-relationship-as-ordering-not-as-tabs).

## D9 — The site is a work sample

**Decided 2026-08-08.** Positioning: *"make people really see what I am about even as a junior."*

An established studio can run on Squarespace because the client list carries the credibility. **A junior has no such cover.** For this site, interface craft is *itself* evidence of motion capability — part of the argument, not a distraction from it.

**This overrides the earlier "don't over-engineer" caution**, which was drawn from studio references whose situation does not apply here.

**What still holds:** craft means a coherent *system* — see the [motion tokens](07-visual-language.md#motion-as-a-system--the-vucko-pattern) — not accumulated effects. That distinction was the audit's actual point.

**Follows from this:**
- Depth beats breadth — process-led case studies prove thinking
- Awards and credits are structural, not incidental — adopt the Burocratik [`/recognition`](07-visual-language.md#two-structural-ideas-worth-taking) pattern
